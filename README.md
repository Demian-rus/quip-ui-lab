## Реальные различия

| Вариант | Организация | Что сравнивать |
| --- | --- | --- |
| A — Каталог | Главное меню → расширяемый каталог → одна страница настройки | Одна прокрутка, три смысловых раздела, дополнительные правила раскрываются на месте. Тип игры меняется через каталог. |
| Б — Мастер | Главное меню → Игра → Игроки → Правила → Старт | Постоянная оболочка и индикатор этапов. Можно вернуться на любой этап; финальный обзор позволяет проверить выбор. |
| В — Консоль | Главное меню → обзор всей конфигурации | Крупная цель и время, пара участников, получатель очков и все активные иконки видны сразу. Нажатие на параметр открывает редактор ниже обзора в том же пространстве. |

Все три используют **одну модель, одни данные и одинаковые начальные параметры**. Тип игры, игровой режим и сценарий/пресет не смешиваются. Новые пресеты или механики не выдуманы.

## Возможности

- Каталог стандартной и тематической игры; настоящие темы v89: География 406, Животные 457, Наука 582 задания. Биология, История, Культура честно помечены «Скоро» и недоступны.
- Выбор двух разных демонстрационных участников; никаких настоящих профилей.
- Получатель очков, четыре сложности, база времени 30–90 с с шагом 5.
- Цель 15–100 очков с шагом 5 либо 2–100 чётных ходов.
- Риск, случайные усложнения, их частота 10–100% с шагом 5, виды текстовых заданий.
- Восемь настоящих иконок работают как toggle. Единая кнопка «НАСТРОЙКИ РЕЖИМОВ» стоит над сеткой; индивидуальных шестерёнок нет.
- В общем центре видны все восемь режимов, действующие награды и особенности. Реально меняются русские/иностранные источники «Напой», минимум один.
- «Данетки» доступны только при получателе «отгадывающий». В тематических наборах нет «Напой» и фразеологизмов; несовместимые режимы отключаются без подмешивания общего словаря.
- Блиц: 3 слова, за полный результат 2 базовых очка, неполный — 0; без выбора числа слов. Примерно — без таймера/риска/усложнений. Секретка — обязательное усложнение +1 к базе 2.
- Back, Escape, browser Back/Forward и восстановление фокуса/прокрутки работают в рамках страницы.
- «Начать игру» ведёт на явно помеченную демонстрационную сцену v88: карточка раскрывается без сдвига; верхний слот меняется на статическое изображение таймера. Это **не движок игры**: нет реального отсчёта, RNG, начислений, партий или статистики.

## Изоляция

Исполняемые модули лаборатории не обращаются к `localStorage`, `sessionStorage`, IndexedDB, CacheStorage, service worker или сетевым API. Всё состояние живёт в памяти страницы и сбрасывается при reload. History API хранит только маршрут внутри прототипа, не игровые данные.

Нет manifest, PWA-установки, регистрации SW, оценок/жалоб, backend или телеметрии. CSP запрещает соединения `connect-src 'none'` и workers `worker-src 'none'`. Фоны, иконки, CSS и шрифты загружаются с самого сайта; внешних runtime-запросов нет.

**Не открывать и не менять Pages основного quantum-portal.** Отдельный путь github.io сам по себе не изолирует origin; поэтому никаких операций с общим браузерным хранилищем в лаборатории вообще нет.

## Запуск и тесты

Требуется Node 22+ и HTTP (ES-модули не запускаются двойным кликом через file://).

```bash
npm ci --ignore-scripts
npx playwright-core install --with-deps chromium --only-shell
npm test
npm run test:browser
python3 -m http.server 8765 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8765/`, затем `/a/`, `/b/`, `/c/`.

Smoke сам поднимает локальный HTTP-сервер и закрывает его. `CHROME_BIN` позволяет указать готовый Chromium. Для повторной проверки уже опубликованной лаборатории можно задать `LAB_URL` с её точным корневым URL и завершающим `/`.

## Проверка владельцем

1. Пройти один и тот же выбор в A/Б/В: стандартная → участники → очки отгадывающему → средняя → 75 с → 18 ходов.
2. Выключить/включить режимы, открыть единый центр и выбрать иностранные источники «Напой».
3. Вернуться назад, проверить сохранённый выбор, открыть дополнительные правила.
4. Сменить тип на тематический, выбрать Географию, проверить недоступность песен.
5. Перейти на демонстрационную сцену, открыть/скрыть карточку и вернуться.
6. Сравнить количество переходов, удобство нахождения параметров, читаемость и ощущение единого пространства.

Не выбирать победителя только по скриншотам. Физический Android и его системный Back/клавиатура проверяются владельцем после публикации; Chromium с touch не заменяет эту приёмку.

## Публикация и повторное развёртывание

Новый публичный репозиторий `Demian-rus/quip-ui-lab` уже создан, Pages использует GitHub Actions. Публиковать только содержимое этой лаборатории. В новом репозитории разрешён main; main quantum-portal защищён условием задачи.

1. Создать новый публичный репозиторий под аккаунтом владельца, без приватных данных.
2. Отправить подготовленный main. Не назначать/изменять remotes или настройки исходного quantum-portal.
3. В **Settings → Pages** именно нового репозитория выбрать **GitHub Actions**.
4. Запустить `UX Lab checks and Pages`. Workflow сначала выполняет Model/Browser, затем публикует только `index.html`, `a/`, `b/`, `c/`, `shared/`; тесты и артефакты на сайт не попадают.
5. Дождаться SUCCESS проверок и deployment. Открыть фактический URL из output `page_url`, проверить HTTP 200, ресурсы и три отдельных URL. Повторить smoke с `LAB_URL`.
6. Только после этого сообщать публичные ссылки владельцу. До этого никакие предполагаемые github.io URL не объявляются рабочими.

Домен, платный сервис, production backend, секреты и включение синхронизации не требуются. Никакие варианты не переносятся в основную игру автоматически.
